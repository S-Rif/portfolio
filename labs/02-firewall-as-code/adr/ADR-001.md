# ADR-001 · Moteur de pare-feu du lab

- **Statut** : proposé
- **Lab** : 02 · Firewall as Code

## Contexte

Le lab doit tourner gratuitement, en CI, et rester transposable aux pare-feu rencontrés chez les clients (Fortinet en tête).

## Options

| Option | Coût | Avantages | Limites |
| --- | --- | --- | --- |
| nftables en conteneur | 0 € | Léger, testable en CI, standard Linux | Pas d'interface constructeur |
| FortiGate-VM | 0 € en évaluation limitée, payant sinon | Proche du terrain client | Lourd, licence, difficile en CI |
| OPNsense en VM | 0 € | Interface complète | VM lourde, API moins adaptée au test automatisé |

## Décision

nftables en conteneur pour le lab et la CI. La même `policy.yml` alimente un playbook FortiGate en bonus : la valeur est dans la source unique, pas dans le moteur.

## Conséquences

- (+) 0 €, rejouable par n'importe quel étudiant.
- (−) La démonstration FortiOS reste un bonus, prouvée séparément.

## Déclencheur de revue

Un client exige une preuve sur FortiOS, ou la licence d'évaluation permet une exécution en CI.
